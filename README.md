# TRUSTX AI — Universal AI Trust Verification and Risk Analysis System
**Evidence Before Trust • Independent External Verification Layer**

TRUSTX AI is an independent verification platform designed to evaluate content generated by external AI assistants (ChatGPT, Gemini, Claude, and local LLMs). Instead of replacing conversational AI tools, TRUSTX AI accepts generated output, extracts individual factual assertions, retrieves corroborating evidence via Google Search grounding, audits research citations against Crossref and OpenAlex, detects internal contradictions and temporal conflicts, and statically scans submitted code for security vulnerabilities.

## The Six Core Verification Modules

1. **Intelligent Claim Extraction**: Deconstructs unstructured AI responses into atomic propositions, preserving context and classifying statement taxonomy (historical, scientific, technical, statistical, biographical, research, general).
2. **Evidence-Based Fact Verification**: Queries Google Search grounding to retrieve authoritative live sources. Categorizes claims into `SUPPORTED`, `REFUTED`, or `INSUFFICIENT_EVIDENCE` with confidence metrics.
3. **Hallucination & Contradiction Detection**: Cross-examines statements within the same response to identify internal timeline contradictions (e.g., conflicting founding dates) and flags unsupported assertions.
4. **Research Citation Verification**: Audits academic references against Crossref and OpenAlex APIs. Resolves DOIs, publication years, and author rosters to expose fabricated academic citations.
5. **AI-Generated Code Security Analyzer**: Scans Python, JavaScript, TypeScript, and Java for hardcoded API secrets, SQL injection concatenation, unsafe dynamic `eval()`, OS command execution, and insecure deserialization without executing code.
6. **Multi-Dimensional Explainable Assessment**: Synthesizes transparent scores (Factuality Alignment Index, Evidence Coverage Index, Contradiction Frequency, Citation Reliability, and Code Security Posture) with deterministic qualitative labels.

---

## Mathematical Formulations

- **Factuality Alignment Index**:
  $$\text{Factuality} = \frac{\text{Supported Claims}}{\text{Supported Claims} + \text{Refuted Claims}}$$
- **Evidence Coverage Index**:
  $$\text{Evidence Coverage} = \frac{\text{Supported Claims} + \text{Refuted Claims}}{\text{Total Verifiable Claims}}$$
- **Division by Zero Protection**: If no evaluable claims exist, the system explicitly displays `"Not enough data"`.

## Prerequisites & Installation

### Requirements
- Node.js >= 18.0.0
- npm or bun

### Local Setup
1. Clone the repository and install dependencies:
   ```bash
   npm install
   ```

2. Configure environment variables in `.env`:
   ```bash
   # Gemini API Key (obtain from Google AI Studio)
   GEMINI_API_KEY="your_gemini_api_key_here"

   # App URL
   APP_URL="http://localhost:3000"
   PORT=3000
   ```

3. Ensure `firebase-applet-config.json` is present in the workspace root with valid Firebase credentials.

4. Run the development server:
   ```bash
   npm run dev
   ```

5. Build for production:
   ```bash
   npm run build
   npm start
   ```

## Static Code Security Rule Catalog

| Rule ID | Name | Languages | Severity | Description |
|---|---|---|---|---|
| `SEC-CRED-001` | Hardcoded API Key or Secret Token | Python, JS, TS, Java | **Critical** | Plaintext API credentials or secrets committed to code |
| `SEC-CRED-002` | Hardcoded Database Password | Python, JS, TS, Java | **Critical** | Plaintext database connection URIs |
| `SEC-SQLI-001` | SQL Injection via String Concatenation | Python, JS, TS, Java | **Critical** | Unescaped string concatenation inside SQL queries |
| `SEC-EXEC-001` | Unsafe Dynamic Code Evaluation | Python, JS, TS | **Critical** | Runtime invocation of `eval()`, `exec()`, or `Function()` |
| `SEC-CMD-001` | Dangerous OS Command Injection | Python, JS, TS, Java | **High** | Unsanitized calls to `os.system()` or `shell=True` |
| `SEC-DESER-001` | Insecure Object Deserialization | Python, Java | **High** | Unsafe deserialization using `pickle` or `ObjectInputStream` |
| `SEC-CRYPTO-001`| Broken Hash Algorithm (MD5/SHA-1) | Python, JS, TS, Java | **Medium** | Collision-vulnerable hash algorithms for sensitive data |
| `SEC-PATH-001` | Path Traversal Vulnerability | Python, JS, TS, Java | **High** | Unchecked filesystem paths constructed from client parameters |

## Limitations & Ethical Disclosures

- **No 100% Infallibility Guarantee**: TRUSTX AI performs empirical correlation against external sources, but cannot guarantee 100% truth.
- **Sandboxed Static Code Analysis**: Code is analyzed strictly via pattern-matching and AST parsing; code execution is strictly prohibited.
- **Academic Index Scope**: Non-indexed workshop papers or books may appear as `UNVERIFIED`; the system does not declare citations fake solely based on absence from a single database.
